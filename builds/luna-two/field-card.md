# The Aperture Slip

*A pocket instrument for a blank result*

> A witness does not flood the room with light. The witness admits a strip of it.

## Position

**DERIVED:** “I did not detect X” reports an outcome under a method. “X is absent” reaches further. That wider sentence is warranted only when its boundary is explicit and the method could examine that boundary for the kind of X in question.

**CONJECTURE:** writing the boundary beside the result will make it easier to catch a sentence that quietly grows after the search. This has not been tested with readers or real investigations.

## Fill the slip before saying “absent”

```text
TARGET      What exact thing, text, or behavior were you looking for?
BOUNDARY    Which files, screen, device, version, place, or record were in scope?
APERTURE    What method looked, and what signal would count as a find?
EXPOSURE    When, for how long, or across which items did it look?
OUTCOME     FOUND / NOT DETECTED / NO ACCESS / AMBIGUOUS / NO RECORD HERE
SENTENCE    What is the strongest claim these fields actually support?
```

Keep the result words distinct:

- **FOUND** — the named signal appeared within the stated boundary.
- **NOT DETECTED** — the method returned no signal within the stated boundary and exposure.
- **NO ACCESS** — some or all of the boundary could not be examined.
- **AMBIGUOUS** — a possible signal appeared, but the method could not classify it.
- **NO RECORD HERE** — the named record contains no report. This says nothing by itself about whether the event occurred.

**DERIVED:** “absent from this exact closed list” can be a sound claim if the list is fully enumerated and the target can be compared against every entry. The claim stays inside that list. A blank result from a partial or inaccessible search is not the same result.

## Three invented cases

All examples below are invented; they describe no real person or observed system.

1. A folder contains `bluebird.txt`. A search looks only through Markdown pages and returns no match for “bluebird.” **NOT DETECTED** is supported for the pages examined. “The folder contains no bluebird” is not: the chosen aperture skipped the text file.
2. A directory listing returns nothing because permission is denied. The result is **NO ACCESS**, not **NOT DETECTED**; the method never reached the target boundary.
3. One browser opening shows a moving dot on one screen. That witnesses the named visual motion in that opening. It leaves touch input, keyboard use, other screen sizes, and later versions untested unless those claims receive their own observations.

## A two-minute practice

Take one blank result from a search you already made. Fill the six fields. Then write two sentences: the narrowest supported one, and the tempting broader one. Circle any word in the second sentence that reaches outside `BOUNDARY`, `APERTURE`, or `EXPOSURE`. Narrow that sentence until every noun and verb fits the slip.

If you have no live example, use invented case 1 and fill it in. The expected outcome is **NOT DETECTED** for the Markdown pages; the `.txt` file remains outside that aperture.

## Limits and falsifier

**UNVERIFIED:** this card has not been tried by an outside reader or used to audit a live build. It is a reasoning aid, not a guarantee of exhaustive coverage or honest reporting.

**Falsifier for the card’s central rule:** give a complete slip whose boundary, aperture, and exposure are accurate, where the target is known to be present inside the boundary but invisible to the named method, and show that the card still instructs the writer to report **ABSENT**. One such case means the outcome rules need repair. Mica owns that repair.
