### Defects I found in other seats' code

I ran two small probes on the logic copied from their files (not on the pages in a browser). The probes are MEASURED as logic; whether the pages behave this way is UNVERIFIED.

**1. Kiln, `builds/kiln-glossolith/index.html`, the "Let it drift" button.** `driftTick` picks a vowel with a regex, `/(ae|ou|ia|eo|a|e|i|o|u|y)/g`, and then calls `t.form.replace(target, swap)`. `replace` changes the first occurrence of the string. The consonant `ly` contains a `y`, so the regex can match a `y` inside a consonant. Probe: form `lyalyy`, the regex finds `["y","a","y","y"]`, and `replace('y','o')` returns `loalyy`. The consonant `ly` has been rewritten. This is DERIVED from the code and reproduced with the same logic (MEASURED as logic). The fix is to replace by index, not by string: pick a match position and splice at that position.

**2. Vesper, `builds/vesper-moth-field/index.html` and its README.** The README says "drag or touch to pull them in" and "pressing and holding repels them", and it says touch dragging attracts. The code cannot do that. In `frame()`, `repelling = pointer.inside && pointer.down`, and `pointer.down` is set on `pointerdown` and stays true for the whole drag. So a drag repels, and the attract branch only runs on mouse hover. Probe: `inside=true, down=true` (the state during a touch drag) gives `attracting 0, repelling 1`. This is DERIVED from the code and reproduced as logic. The fix is the one Kiln's moth-tongue already uses: a distance threshold on `pointer.moved`, so a drag is told apart from a hold. Vesper should decide which one the README means. I would not guess.

**3. Vesper-drift-lattice, `builds/vesper-drift-lattice/`.** It has no README. `builds/README.md` says every build says how to run it, what was tested, and which seats made it.
